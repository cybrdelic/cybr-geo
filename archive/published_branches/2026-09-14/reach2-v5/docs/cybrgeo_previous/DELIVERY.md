# Delivery inventory and publication status

The complete extracted workspace contains all three supplied differential stages, all retained images/videos/meshes/STEP files, the76-body manufacturer motor model, the200-mesh custom drive study, new footage and all three whiteprint sheets. `delivery_manifest.json` is a per-file byte-count/SHA256 inventory for the complete download. It is generated by `tools/package.py`.

The initial GitHub publication is the **source and README-preview checkpoint**. Do not interpret a successful source-publishing workflow as proof that the original large binary files have been transferred. The original high-resolution differential geometry/media are in the complete downloadable workspace supplied with the project delivery. Their source and documentation are retained in GitHub; missing binary files must be restored from that complete workspace before those archived commands run. The separate motor reproduction workflow can populate its CAD and renders from the pinned manufacturer reference.

To publish the complete extracted binary payload using an authenticated local Git installation, first run `python tools/audit_delivery.py`, then `python tools/publish.py --push`. The latter never force-pushes and preserves the repository's existing LICENSE.

No transport error is represented as an empty or completed asset publication. Generated concept imagery remains labeled as reference-only, not new CAD rendering.

# AERIS / CYBR GEO geometry showcase

A complete, original **serviceable benchtop extraction-turbine concept**, built with
CYBR GEO / Mechanism Lab. It is intended as a useful design and geometry
inspection example, **not as a rated fume-extraction or respiratory-safety product**.

The same named assembly drives analytic CAD export, full mesh export, rigid
animation, real Boolean cutaway, photographic rendering and analytic whiteprints.
There is no generated photograph, pasted reference image, or shader standing in
for the blades, holes, pleats, wires or internal lattice.

## What is actually modelled

The 215 named components include a pocketed base and connected tilt yoke;
an asymmetric hollow collection hood; bolted cartridge flanges; a real folded,
finite-thickness filter sheet and crossing-wire support grille; a one-solid spiral
volute with an integral open rectangular outlet flange; eleven twisted lofted
impeller blades, shroud, back disk and revolved hub; a continuous shaft and two
ball-bearing assemblies; an original finned motor with stator teeth, magnet
sectors and individually routed copper conductors; a hollow terminal enclosure;
a continuous spline harness with a real helical strain-relief sweep; and a
windowed outlet cartridge containing both an analytic BCC lattice and an implicit
gyroid sheet.

The default model is approximately 366 x 240 x 302 mm overall. These are mesh
bounds, not toleranced fabrication dimensions. It contains roughly 1.65 million
triangles. Exact fresh counts and bounds are written to `validation.json`.

mechanism recipe, gear generator or possible kernel operation is exercised.

## Reproduce

From the repository root, in the documented Linux/WSL environment:

```bash
python -m pip install -r requirements-tested.txt
python -m pip install --no-deps -e .

# Build the real solids, full meshes, cutaway, STEP, BOM and animated GLBs.
python examples/aeris/build_assets.py --out build/aeris --exports

# Geometry, real CAD contacts and serialized-export verification.
python examples/aeris/verify.py --out build/aeris --cad

# Five native path-traced stills, each freshly rendered from geometry.
python examples/aeris/render_assets.py --out build/aeris \
  --views hero cutaway exploded rotor_detail topology_detail \
  --size 1440x936 --spp 384 --threads 4 --depth 12

# Analytic four-view A3 drawings: SVG, vector PDF, DXF and PNG previews.
python examples/aeris/draw_assets.py --out build/aeris

# Separate, explicitly labelled VTK PBR inspection films, not path-traced films.
python examples/aeris/video_assets.py --out build/aeris --fps 24
```

FFmpeg, CMake, a C++17/OpenMP compiler, Cairo and Mesa/EGL are required by the
relevant pipelines. The repository's tested dependency versions are pinned.
Local `assembly.pkl` and `cutaway.pkl` are CAD working caches generated by the
build command; **never load an untrusted pickle**. They are not portable release
formats and are excluded from the distribution package. Rebuild them for CAD
checks and drawings. NPZ caches retain meshes, not analytic BReps.

A quick inspection render can use `--preview --size 768x500 --spp 32`. `--pbr`
selects the separate VTK raster renderer; it does not become path tracing merely
because its materials are physically based.

## Rendering provenance

`render_assets.py` calls CYBR GEO's existing `render_photoreal` function. The
retained native BVH/GGX/MIS transport, thin-lens camera and explicit material
microfinish are used. Materials include petrol anodized aluminium, satin alloy,
stainless hardware, copper conductors, elastomer and a visual filter substrate;
these are original appearance choices, not measured material data.

A small generic fix to `native/photoreal.cpp` scales the stock softbox positions
and dimensions with the assembly bounds and raises lights that would cross the
studio floor. The original fixed-millimetre light rig could intersect larger
assemblies. This changes the existing photographic studio, not the geometry or
the underlying path integrator.

At 384 samples per pixel the existing renderer applies **no denoising**. The
sidecars record the actual resolution, samples, bounce limit, lens, focus,
rendering duration, truth classification and final PNG checksum. Lower-sample
previews use the repository's disclosed conservative guide-aware filtering.

## Verification and engineering limits

`verify.py` checks the complete geometry contract, feature references, rigid
rotor coupling, shaft/bearing envelopes, invalid parameter guards, decoded GLB
units and node transforms, actual animation buffers, honest STEP coverage,
watertight oriented gyroid topology, valid positive-volume analytic components,
a genuinely one-solid volute casting, actual blade/disk contacts and a real CAD
half-section with zero residual volume in the removed half-space. The result is
written to `verification.json`; a test definition alone is not a passing run.

**202 components have analytic CAD. Thirteen are mesh-only:** the gyroid and
twelve conductor windings. They remain in the full GLB and are explicitly omitted
from STEP. `aeris_analytic.coverage.json` names every inclusion and omission.
The BCC lattice is an overlapping valid BREP compound, not a fused manufacturing
solid. Nominal screw shanks have real hex sockets but no claimed thread helices.

The rotor animation is prescribed at 15 rpm. The 2.8 mm nominal radial envelope
clearance does not establish full interference clearance, bearing suitability,
loaded contact, structural integrity or balance. No fan curve, pressure drop,
filtration efficacy, capture velocity, acoustics, electrical safety, thermal
performance, fatigue life or manufacturing release is claimed. A real extractor
would require those analyses and physical tests before use.
